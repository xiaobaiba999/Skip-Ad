## 一、内置规则库与订阅市场规则的使用顺序与命中问题（根治）

### 旧序的三处病灶

1. **市场规则被饿死（跨源短路）**：`SubscriptionManager.match` 先试内置订阅、内置命中即短路返回——
   远程订阅（市场源·日更·610+ 款）只在内置整窗无命中时才轮到。同一应用两源都有规则时，
   内置静态快照（21 款 vid 规则·2026-05 vintage）常年压在市场新规则前面——
   「订阅市场导入了怎么还是不跳」的元凶。
2. **专属规则被饿死（源内顺序）**：`Subscription.parse` 把 globalGroups 解析进 `apps` 时排在
   apps[] 之前——泛化全局规则（`[text*="跳过"][text.length<10]` 类）反先于该应用的精准专属规则
   （带 activityIds/精确选择器）被尝试。
3. **单源单候选拖死整轮**：订阅只贡献一个命中进点击轮换；该候选失效（点击落空）后没有第二源
   候选可换——复验「换候选」换的是同一个源的同一个目标。

### 新序（v7.1.0 唯一裁决处：core/RuleRouter.java 纯函数）

```
主引擎五层文本规则（探针 0ms，不动）
  → 市场源（用户导入·日更·该应用有专属规则时优先）
  → 内置源（APK 静态快照）兜底
  → 全局组（globalGroups）垫底
两源各贡献一个候选进点击轮换：文本候选用尽 → 市场候选 → 内置候选 → …
```

- 风险面零扩张：远程命中仍过全量既有安全闸（activityIds 强校验 / skip 形态门 /
  safeGlobalLabel 诱导词否决 / 面积 ≤35% 门 / validSkipTextShape）——只动顺序，不动闸门。
- 源命中分账：`builtinHits` / `remoteHits` 分别记账（订阅页「命中」+ 使用报告可见对比）。
- 订阅命中日志带源标注：`rule_sub_gkd_remote`（市场源优先）/ `rule_sub_gkd_builtin`（内置源兜底）。

### 扫描日志信息（使用顺序问题可见化）

- `logScanMiss` 新增订阅两源覆盖诊断：`❓ 开屏未命中（x.y）… · 订阅[市场覆盖+内置覆盖] ——上传日志可帮我们补规则`
  ——用户上传日志后直接看到该应用的规则覆盖状态，「导入了怎么还是不跳」类问题可远程定位。

## 二、底层算法优化

- **分应用规则行预筛 memo（RuleEngine.rowsFor）**：matchText 每节点线性扫全部 ~50 行做包名
  startsWith 前缀比对（一窗 ~340 节点 × 50 行 = 17,000 次串比对）→ 按 pkg 每窗一次预筛
  （`ctx.appTextRules`），命中行从 50 收敛到 0~3 行，后续每节点零前缀比对；探针/DFS 双路径共享。
- **工程纪律**：首版实现回落路径丢了包名前缀检查（任意包名会误命中分应用文案）——被新增
  RuleOrderTest 当场抓红，修复为「统一走 rowsFor(pkg)」并与旧「全表+前缀检查」做数学等价论证：
  rowsFor(pkg) 恰返回 row[0] 是 pkg 前缀的全部行，绝不漏也绝不误（39 项断言锁死）。

## 三、信息流广告卫士（FeedAdGuard 自 v6.2.0 已验证实现移植）

- 用户原话：「能不能增加功能实现自动关闭 app 内的广告内容，例如微信朋友圈就有广告穿插在朋友圈之中」。
- v6.2.0 的 FeedAdGuard（81 项单测全绿的已验证实现）整体移植回 7.0 稳定基座，接线零改动：
  - **两段式**：P1 点「广告/就业/求职/招聘/职位」披露角标拉起关闭菜单 → P2 点
    「关闭该广告/关闭此广告/屏蔽此广告/关闭广告/不感兴趣」中性项收起。
  - **四道安全闸（宁漏勿误红线——绝不点广告主体）**：① 角标词精确等值（>6 字必是正文·
    纯符号尾单收）② 角标面积门（宽 ≤35% 屏 × 高 ≤8% 屏）③ P2 中性项双闸（强特征 ≥1 且
    总数 ≥2·须 P1 出手 8s 指纹窗内——用户自己长按的菜单绝不对抗）④ 名单门（18 款信息流 App
    + 微信只认 sns 族窗——聊天主界面零扫描红线保持）。
  - **功耗双闸**：1.2s 扫描节流 + 300 节点预算（与开屏路径互不挤占；开屏窗期内让路）。
  - **既有防线免费复用**：出手走 execute()（用户让路/耐心预算/F·H 多点防线/人手手势派发/
    feed 专用边界终闸 ComplianceGuard.feedBoundaryCheck）。
