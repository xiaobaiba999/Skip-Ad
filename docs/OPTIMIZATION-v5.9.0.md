## 一、误触根因定位（旧算法三缺陷）

旧行为：`clickNode` 对决策携带的标签 bounds 直接取 `(l+r)/2,(t+b)/2` 几何中心派发手势。设备差异下的三类事故面：

| # | 场景 | 旧算法行为 | 真实后果 |
| --- | --- | --- | --- |
| ① | 标签被父容器/滚动裁掉一半（低端机开屏布局挤压常见） | 中心落在【不可见区】 | 手势点到旁边内容——720p 低端机上点中「立即下载」 |
| ② | 分屏/折叠自由窗口/内外屏切换 | 中心在应用自身窗口外 | 触点落到【另半屏他应用】= 误触他 App |
| ③ | 输入法/悬浮球/他应用 overlay 在 Z 序之上 | 无判定，照发 | 触点被覆盖物截走——键盘上乱打字/点掉验证码横幅 |

多点/无点现象与根因的对应：
- **「无点」**= ②③（点出去了但落在窗外/覆盖物上——无效果）+ ①（点在不可见区——无效果还可能误触）；
- **「多点」**= 无点之后复验链换候选重试，若几何死区未修，同坐标盲刺反复发生（旧逻辑同候选每次都点同一几何中心），点击预算被无效重试烧完。

## 二、TapPoint 四层防线（新核心 `core/TapPoint.java`，纯函数）

### 2.1 L1 祖先可见交集（`visibleBounds`）
沿祖先链逐层求交（≤64 层防超深树），任一祖先（或自身）`visible()==false` → 返回 null 拒点——被完全裁掉/被遮挡（`isVisibleToUser` 已含被其他窗口遮挡语义）/显式隐藏的标签绝不派手势。**标签被裁一半时，剩余可见矩形成为唯一合法落点域**。

### 2.2 L2 节点窗口钳制（`tapRect`）
标签矩形 ∩ **节点自身窗口** bounds（`AccessibilityNodeInfo.getWindow()`——分屏/多窗/弹窗下最精确的归属窗；拿不到时回退 `getRootInActiveWindow()` 根窗 bounds）。无交 → null：**分屏另半区/折叠切换残留的旧坐标绝不盲点**。

### 2.3 L3 安全选点（`pick`）
| 机制 | 参数 | 作用 |
| --- | --- | --- |
| 中心正解 | attempt=0 | 可见矩形中心=用户看得见的位置 |
| **复验象限轮换** | ROTATION_SLOTS=5（中心+四象限中心） | 同候选第 N 次复验换象限点——「多点」根治：设备死区/命中测试盲区不再重复盲刺同一坐标 |
| 边缘内缩 | EDGE_INSET=6px（小矩形自动收窄到边/4） | 圆角/水波纹边缘/刘海安全区死区零接触 |
| **盲刺拒绝** | MIN_VISIBLE_SIDE=12px | 可见缝过小时点了大概率落旁边未知物——宁可拒发手势走无障碍代点 |
| 形变防死区 | 扁（宽≥2×高）纵向恒居中 · 竖窄（高≥2×宽）横向恒居中 | 横幅状跳过条的上下边是死区高危带，轮换绝不把点推向死区 |

> 形变防死区是测试先行抓出来的：S8 场景（24 类几何全挂）暴露了「象限轮换双向偏移」与设计意图（扁标签纵向恒居中）的偏差——修正为按宽高比分轴轮换。这正是矩阵测试的价值。

### 2.4 L4 覆盖层 Z 序判定（服务侧 `pointCoveredByUpperOverlay` + 纯函数 `coveredByUpperWindow`）
`getWindows()` 按 Z 序（索引小=层级高）返回：先定位活跃窗（我们的广告窗），其上的**任意**窗口 bounds 包含触点 → 手势必被截走 → 拒发手势。覆盖 v3.13.0 只拦 SystemUI 顶条的全部漏网面：

| 覆盖物 | 旧（v3.13.0） | 新（v5.9.0） |
| --- | --- | --- |
| heads-up 验证码/短信横幅 | ✅ 拦 | ✅ 拦（同一机制） |
| **输入法键盘**（弹起盖住下半屏跳过键） | ❌ 漏（点中乱打字） | ✅ 拦 → 降级代点 |
| **他应用悬浮窗/悬浮球** | ❌ 漏（误触他 App 功能） | ✅ 拦 |
| **状态栏/导航栏条带**（贴边跳过键） | 部分 | ✅ 全拦（不拉下通知栏） |
| 查不到活跃窗（过渡态/特殊 ROM） | — | 退化旧行为（绝不错杀） |

拒发 ≠ 放弃：`clickNode` 自动降级 `performAction` 无障碍代点（不经屏幕坐标，点击直达语义目标，绝不碰覆盖物）；再失败由复验扫描换候选（`TapGestureCallback.onCancelled` 350ms 快扫链保持）。

### 2.5 服务侧接线（`AdSkipService`）
- `clickNode`：原始几何中心 → `adaptiveTapPoint(d)`（tapRect + pick）；
- `clickAttemptNow`：execute 出手前写入本窗已点击次数——象限轮换基数；
- `nodeWindowBounds/activeWindowBounds`：L2 的窗口 bounds 源（节点窗优先/根窗兜底）；
- 触点拒发/覆盖层保护日志（同包 10s 节流）：拒发原因可诊断（不可见/被裁/窗外/被覆盖）。

**成本核算**：L1 祖先链 = 纯内存矩形求交（无新增 IPC）；L2 一次 `node.getWindow()`（点击路径，同窗 ≤12 次）；L4 一次 `getWindows()`（与 v3.13.0 起 `headsUpBanner` 同路径同量调用——成本持平）；功耗红线零压力。
