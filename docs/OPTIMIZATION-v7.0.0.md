## 二、订阅导入永不失败（要求 2 · Connection reset 终根治）

**v6.1 复盘**：五通道镜像（cdn→fastly→ghfast→gh-proxy→raw）+ 同址重试在用户网络下仍全失败——单点镜像池太小，且失败等待黑盒（8s×5 通道无进度感）。

**v7 双手根治**：
1. **八通道镜像链**（`core/SubMirrors` 纯函数，JVM 断言锁定顺序）：原址 → fastly.jsdelivr → gcore.jsdelivr → testingcf.jsdelivr（jsdelivr 三接入点——重置概率互相独立）→ ghfast.top 代理 → gh-proxy.com 代理 → raw.githubusercontent 直连；每通道同址瞬时故障重试（600ms，仅 reset/timeout/EOF 类）；任意接入点变体作输入展开同一条链（归一化）。
2. **离线快照兜底**：三个市场精选源（Lin-arm 1.39MB / ganlinte 610KB / 小年侠 598KB）的最新内容随 APK 内置 `assets/subsnap/*.json5`（aapt2 deflate 后合计 ~520KB，APK 310KB→808KB）。**全通道失败 → 直接导入快照**（结果标注 `snapshot:true`，UI 显示「已导入(离线) ✓（联网后自动更新最新版）」），`subSnapshotPending` 置位 → 心跳 1 小时即重拉真源（恢复联网自动换最新版）。**导入路径从此永不硬失败。**
3. **进度实时反馈**：`SubscriptionManager.fetch` 每切换通道回调 `ProgressSink` → 桥 `evaluateJavascript("window.__subProgress(attempt,total,host)")` → 页内显示「正在拉取订阅（镜像 3/7 · gcore.jsdelivr.net）…」——等待不再黑盒。

**快照归一匹配**：`snapshotAssetFor` 按 jsdelivr 归一键（owner/repo@branch/path）匹配——用户从历史记录/剪贴板恢复的任何接入点变体 URL 都命中同一快照；自定义链接无快照不兜底（绝不让用户误以为有兜底）。

## 三、版本描述规范与更新流重排（要求 3/4）

- **当前版本**：`CURRENT_RELEASE = { title, summary }`（1 标题 + 1 段落）——我的页「版本记录」卡渲染即此格式。
- **新版本功能描述**：`core/ReleaseNotes` 纯函数解析发布体 → ≤5 条标题；**序号行（1. 2. 3.）优先**（v7 起规范发布体），无序号行回落历史格式（①圈号/- * 列表）；**# 章节名绝不入列**（它是「### 新版本功能」/「## 新版亮点」类元信息，混入只会挤占 5 条名额）；markdown 清洗（链接→锚文本、强调/代码符号剥离）+ 44 字截断。桥通道 `Net.parseRelease` 输出 `headlines[]` 预解析数组（**同步桥**——沿用 v6.0/v6.1 实测形态，绝不引入 v6.4 的异步桥），JS 优先渲染 `d.headlines`、空时回落 JS 同规则解析器。
- **检查更新**：发现新版本 → 就地渲染「新版本功能」编号列表（1. … 5.）+「下载 vX」按钮 +「发现新版本 vX（功能描述如上…）」；已是最新 → 「已是最新版本 · {当前版本标题}」。
- **顶部更新横幅整体移除**：index.html 删 `#update-banner` 全块；app.js 删 `#ub-toggle/#ub-action` 事件链与启动静默检查（启动零网络零提示）——**只有手动「检查更新」能查询/下载**，每次检查只出一条提示信息。
- **界面初始化保险丝**（对 v6.3-v6.5 症状的兜底防线）：index.html 内联 5 秒哨兵——app.js 早期崩溃（顶层空引用等）时把首页占位换成「界面初始化未完成 / 划掉重开（数据不受影响）/ 仍无效覆盖安装即可恢复」可操作指引，绝不出现「永久加载无反馈」白屏。
