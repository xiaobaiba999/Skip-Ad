   363→   363→        /** 自动拉活（v4.4.0 深度拉活版）：
   364→   364→         *  · 服务已运行 → ok（若处于暂停自动解除——用户点「恢复」的意图）
   365→   365→         *  · 设置仍登记且服务死 → 后台线程深挖最长 6s（v3.14.0 只等 1.5s，
   366→   366→         *    MIUI/HyperOS 重绑慢的 ROM 不够→被误判 need_toggle→跳系统设置
   367→   367→         *    看 10 秒强制警告，「恢复防护很麻烦」的元凶）；每 500ms 用
   368→   368→         *    AccessibilityManager 查询踢一次系统（促使 AMS 重绑）；
   369→   369→         *  · 未登记 → disabled 由页面引导开启。
   370→   370→         *  （无障碍服务受 BIND_ACCESSIBILITY_SERVICE 保护，任何应用都不能
   371→   371→         *   start/bind 它；设置页 10 秒强制等待仅剩「开关真被关」时才需要）
   372→   372→         *  返回 JSON：{ok, running?, revived?, resumed?, enabledInSettings?, reason?} */
   373→   373→        @JavascriptInterface
   374→   374→        public String tryAutoRevive() {
   375→   375→            org.json.JSONObject out = new org.json.JSONObject();
   376→   376→            try {
   377→   377→                if (AdSkipService.isAlive()) {
   378→   378→                    boolean wasPaused = !AdSkipService.masterState(a);
   379→   379→                    if (wasPaused) AdSkipService.setMaster(a, true); // 恢复即全开
   380→   380→                    out.put("ok", true).put("running", true).put("resumed", wasPaused);
   381→   381→                    return out.toString();
