# 开屏卫士 v7.15.13（app→app 跳转接管）

> 用户实锤轮：「项目主功能不变，优化从app跳转到另一个app，在跳转到另一个app开屏广告跳转不了或者没触发问题，顺便扫描最新的日志，对不足的地方进行修复」。本轮基于 #110-#115 六台设备最新日志考古，根治跳转到另一个 app 后目标 app 开屏「没触发/跳不了」的三处缺口；主功能 byte-for-byte（决策核心仅新增 isImePkg 纯函数，订阅/规则引擎零改动）。v7.15.12 及之前全部能力保留。

## 死因（#110-#115 日志考古 + 代码走查）

1. **跳转动画期竞速丢弃 + 静态开屏零内容事件（「没触发」主因）**：从 app A 跳到 app B 时，切屏动画期 B 的首个窗口事件因活动窗口归属未切换被前台门竞速丢弃——旧版只登记候选后【被动等待】B 的内容事件复核晋升；而静态开屏（WebView/纯图——#115 dkXAy 跳转落地 app 实锤微树空壳 6/11/25 节点）前 2~3 秒常零内容事件 → 竞速窗 3 秒过期 → 广告与主页同 Activity 时整窗漏拦
2. **首探阴性后 5 秒节流（「没触发」次因）**：无竞速形态（ROM 吞窗）下首探时活动窗还属旧应用 → 阴性；事件仍在流入但旧 5 秒包级节流使下一探最早 +5 秒——5 秒开屏上等于放弃
3. **输入法前台劫持（#114 Sony 实锤）**：评论框键盘起落把前台追踪反复劫走 → 每 5 秒一轮「切换app回归」晋升 + 全量重扫（日志 11:32:33~52 五连发实锤）——键盘是覆盖在真前台应用上的浮层，不是前台应用

## 本次更新

1. **竞速自检梯**：跳转动画期目标 app 窗口事件被竞速丢弃后不再被动等内容事件——登记即排三针主动自检（+0.5/+1.2/+2.4 秒，各一次 binder 根查询），阳性证据（根节点包名==该包）才晋升，晋升=完整进入重置 + 立即补扫，日志「🔄 跳转接管」；静态 WebView/纯图开屏零事件形态整窗救回
2. **探针阴性快重试**：切屏动画期首探阴性（根还属旧应用）后，3 秒窗内 5 秒节流降为 800 毫秒快档连探（阳性/晋升即关窗）——动画期误阴性不再拖过整个开屏
3. **输入法零前台劫持**：键盘起落绝不写前台追踪（IME 族包零扫描零点击照旧；设置/锁屏等真实前台切换照旧）——评论页键盘起落不再触发每 5 秒一轮的晋升循环 + 全量重扫（功耗净减）
4. **回归防线**：服务级新增 S15 app→app 跳转十三项（竞速自检梯四项：登记/晋升/日志/静态开屏补扫跳过；阴性快重试五项：记账/不误晋升/800ms 档放行（旧 5s 档必挂的回归红线）/回归日志/补扫跳过；IME 零劫持四项：基线/不劫持/零晋升日志/设置页负例对照）——服务级 48 项全绿；核心 4530 断言零改动全绿；主功能 byte-for-byte
5. **binder 红线保持**（<50 次/秒）：新增最坏 +3 次/跳转（3 秒竞速窗 ≈1 次/秒）+ 快重试 ≤4 次/3 秒——均为红线的 1/40；IME 修复为净减项（晋升循环的周期性探针 + 全量重扫链消失）
