# 开屏卫士 v7.15.5（下载通道死局根治 + 开屏扫描误门控解除 + 订阅规则自动瘦身）

> 用户实锤三合一修复轮：① v7.15.1/v7.15.3 检测到新版本后点下载报「下载链接不在允许的发布通道内」；② 很多 App 开屏的广告跳不了、日志也没有记录（规则和日志严格区分开屏广告和插屏广告）；③ 订阅的规则命中很少的去除掉。三案根因各自定位闭合，全部根治。

## 本次更新

1. **下载死局根治（点下载报「下载链接不在允许的发布通道内」）**：死因 = 渠道链首位的 gcore CDN 直链被下载白名单拒之门外，且渠道启动被拒不换备用通道——三件套根治：
   - 白名单收编 jsdelivr 四域（gcore/cdn/fastly/testingcf——仓库 dist APK 官方 CDN 直出通道，与 Release 资产同字节同源；安装前 SHA-256 全量校验闸保持，通道扩张不扩投毒面）
   - 渠道启动被拒自动换备用通道（与「下载失败/30s 无进展」同一换道语义——全部渠道都拒才如实报错，不再死局）
   - 更新清单撤 cdnApkUrl 字段：**v7.15.0~v7.15.4 场端旧版不升级也能恢复**——「检查更新」拉到新清单后点下载，首渠道回到 ghfast.top 镜像（白名单内）即正常；新版客户端改由本地合成 gcore 直链，CDN 优先的可达性保持
2. **开屏全灭 + 零日志根治（头号回归）**：v7.15.0 版本线重制时丢失了旧时间线 v8.1.0 的修复——「习惯学习」开关误门控整个开屏扫描：关掉它 = 全部 App 开屏零扫描、零点击、零日志（「跳不了」与「日志没记录」同源同灭）。本轮：开关回归只管「学习新跳过键」的写入路径；设置页文案同步澄清（关闭不影响已有跳过能力——开屏照跳）
3. **开屏/插屏严格分域（用户指令：规则和日志严格区分开屏广告和插屏广告）**：
   - 路由分域：开屏观察窗内插屏卫士让路（开屏窗归开屏路径独占——主引擎规则 + 订阅 + SDK 直断兜底链；窗落定后插屏接管）——旧版开屏窗第一帧就跑插屏扫描，与开屏路径抢出手、把开屏未命中误记成「插屏未命中」
   - 观察窗分域：SDK 广告窗 12s→20s + 补 14/16.5/19s 扫描档（视频开屏的跳过键常在视频末 5~15s 才露头——12s 硬封顶 = 字面意义的「不再扫」）；普通窗 12s 与功耗红线零变动
4. **日志严格区分广告类型**：开屏出手记「⚡ 开屏跳过」；插屏/信息流路径取消同次出手双日志双计数（此前一次插屏关闭 = ⚡ + 🛡 两条日志 + 两个统计档）；订阅命中携带 GKD 组名——「开屏广告」「插屏广告」等组名直接进日志，规则类型可归因
5. **订阅规则自动瘦身（命中很少的去除）**：市场源（id667 · 610+ 款）某应用规则评估 ≥300 次（跨 ≥3 天）仍零命中 → 自动停用该应用的市场规则；命中过的永不自动停（广告低频 ≠ 规则无效）；停用满 30 天自动复评（订阅日更的规则有二次机会）；内置源不受影响；「我的 → 使用报告」可见停用款数与策略
6. **测试与验证**：JVM 23 套件 4458 断言全绿（新增 SubPruneTest 22 项 + UpdateHostsTest 扩充 23 项 + 订阅组名贯穿断言）；页面资产符号闸 11 项在场通过；密钥泄露扫描全绿；APK 签名证书与历史一致（05ada6e3…）
