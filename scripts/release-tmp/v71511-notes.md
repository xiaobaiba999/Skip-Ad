# 开屏卫士 v7.15.11（锁屏/切换app开屏根治 + 多点治理 + 功耗优化）

> 四台设备 v7.15.10 日志实锤轮（#105 Redmi / #107 Samsung / #108 OPPO / #109 Xiaomi）：「锁屏和切换app的开屏广告仍然未实现，15.10版本甚至还会有多点的情况」。本轮逐一定位死因并根治——主功能 byte-for-byte（决策核心/规则引擎/订阅零改动，全部为恢复链与节流层）。v7.15.10 三图豁免带全部保留。

## 死因（四台设备日志考古 + 代码走查）

1. **锁屏/解锁开屏链死（#109 实锤）**：解锁重入已触发、补扫已跑，但验证码/短信横幅把触点与返回键全挡——横幅 3~8 秒自动消散后系统不再发任何可触发事件，既有链最晚 3.4 秒（晚档梯子 3.2s + SDK 兜底 3.4s）——晚到跳过键（4~6 秒才渲染）与横幅消散后的窗口都是盲区 = 广告白看到底
2. **切换app开屏整窗漏拦**：HyperOS/Android17 回切不发窗口状态事件（v7.12.0 的「前台竞速晋升」修复在 v7.15.0 版本线重制时遗失）——回切后前台追踪停在旧应用，本应用的内容事件被前台门全量丢弃，引擎对回切开屏整窗致盲
3. **多点（#108 实锤：同一秒 5~13 条放行日志连续 7 秒）**：①日志层——每轮扫描每轮都重打「图片跳过键边界放行」，用户读日志 =「点了十几次」（实际出手以 ⚡/🔁 日志为准）；②行为层——手势被覆盖层/横幅拒发后无冷却记账，以扫描节奏每秒 ~2.6 次对同一候选无限重试
4. **功耗（#106 OPPO 实锤）**：静态窗动画/进度条内容事件不停 → 插屏扫描 2.5 秒一轮无限重扫同一面窗（一小时 24+ 轮）；aweme 的 Toast 提示窗被当开屏窗整树扫描

## 本次更新

1. **锁屏/解锁开屏根治**：①横幅让路重排——出手被验证码/短信横幅挡下时排 3 针重查（+2.5/+5/+9 秒），横幅已散且前台未换窗口未切即重排扫描链立即补扫（日志「🔔 横幅已消散」可核验；绝不点掉横幅红线保持）；②解锁晚到键两针——解锁重入链追加 +2.5s/+5.5s 补扫（解锁瞬间广告窗常是空壳、跳过键 4~6 秒才渲染），每次解锁至多两扫
2. **切换app开屏整窗漏拦根治**：前台回归探针——活动窗口归属【阳性证据】复核（查询失败绝不误晋升），到手即按「进入应用」同语义完整重置 + 立即补扫（日志「🔄 切换app回归」）；窗口类语义还原：内容事件的源 View 类绝不写入窗口类表——聊天主界面/小程序容器/密码窗三道零扫描门与根窗口返回键安全门在回切路径照常在岗
3. **多点治理**：①边界放行日志去重（同包同理由 6 秒一条——双向验证：旧代码 22 条 → 新代码 1 条）；②派发失败连击退避——连续 ≥3 次派发失败后 1.5 秒人手耐心节流（首两次快重试保留），成功/横幅消散/新窗即清零
4. **功耗优化**：①插屏窗级退避——同窗连续未命中 2.5s→10s→30s 递进（扫描量降 12~24 倍；窗切换/出手成功即清零，新插层照常秒级响应）；②Toast 类窗零开屏扫描；③securitypermission 零扫描（OPPO 权限详情页族，与 permissioncontroller 同口径）
5. **回归防线（双向验证）**：服务级新增 S10（横幅挡点→消散重排救回）S11（无窗口事件回切→探针晋升补扫跳过 + 聊天主界面回切零扫描负例）S12（日志去重 22→1）S13（插屏退避梯子）——旧代码全红/新代码全绿；服务级 29 项 + 核心 4530 断言全绿
6. **发布前审核轮收口（致命-1）**：晋升路径窗口类语义还原（CONTENT_CHANGED 源 View 类污染窗口类表 → 三道类名级零扫描门旁路的审核实锤修复）+ 息屏闸对称补齐 + Toast 断流前置 + 防膨胀上限补全
